# Supplyo: новая серверная версия, этап 1

Старый PHP-проект, его база и API-ключи не используются. Интерфейс-прототип на порту 8093 остаётся отдельным. Новая версия: http://127.0.0.1:8095.

## Запуск на Windows

Требуется Node.js 24. В PowerShell:

```powershell
Set-Location 'C:\Users\eleg1\Documents\Codex\2026-09-16\new-chat-8\wms-shadcn'
npm.cmd ci
npm.cmd run start:live
```

Открыть http://127.0.0.1:8095/#register. Создать новый аккаунт. Подписка нового аккаунта не активна: подключение API-ключей, запросы заказов и синхронизация заблокированы на сервере. Выбор тарифов доступен в «Настройки → Подписка»; платёжный провайдер пока не подключён, кнопки не выдают фиктивную подписку. Только после подтверждённой активации подписки можно вставить персональный API-ключ WB с правами чтения заказов FBS. Ключ не присылайте в чат. В течение нескольких секунд фоновая задача проверит продавца и загрузит новые заказы. Название берётся из WB, а не вводится вручную. Пустой список после успешного обновления означает отсутствие новых заказов в ответе WB.

Остановка: Ctrl+C в терминале запуска. Для раздельного запуска: `npm.cmd run server` и `npm.cmd run dev:live` в двух терминалах.

## Что реализовано

- Регистрация, вход, выход; серверные сессии в HttpOnly cookie. Пароли хешируются scrypt с индивидуальной солью. Проверяются Origin и заголовок клиентского запроса, ограничены попытки входа.
- Изоляция пользователей по владельцу магазина во всех запросах. API-ключи шифруются AES-256-GCM, не возвращаются браузеру и не сохраняются в localStorage.
- Постоянная очередь в базе: одна активная загрузка на магазин, восстановление после перезапуска, паузы и повтор при временных ошибках. После успеха загрузка повторяется не чаще раза в минуту. Ошибка WB не уничтожает последний успешный снимок.
- Чтение новых FBS-заказов из сохранённого снимка, поиск по номеру/артикулу/баркодам, страницы по 50 строк. Интерфейс опрашивает только свой сервер; в скрытой вкладке опрос приостанавливается.
- Используются только GET `common-api.wildberries.ru/api/v1/seller-info` и GET `marketplace-api.wildberries.ru/api/v3/orders/new`. Сервис не создаёт поставки и не изменяет заказы в WB.

## Данные и ключ шифрования

Локальная PostgreSQL-совместимая база PGlite находится в `.local-data/postgres`, ключ — в `.local-data/encryption.key`. Каталог исключён из Git. Не удаляйте ключ: без него невозможно расшифровать сохранённые API-ключи. Доступ к этим файлам должен иметь только владелец компьютера.

Для согласованной ручной резервной копии остановите оба процесса и скопируйте весь `.local-data` в защищённое место. Ежедневный внешний бэкап и проверка восстановления будут настроены при серверном развёртывании; сейчас они не настроены.

## Границы этапа

Это локальный первый рабочий срез, не готовая многопользовательская эксплуатация. Внешний PostgreSQL, HTTPS/Secure cookie, подтверждение почты, восстановление пароля, юридические документы, биллинг, распределённый планировщик и мониторинг ещё нужны перед публичным запуском. PGlite рассчитан здесь на один серверный процесс; не запускайте несколько процессов с одной папкой базы. Cookie без Secure допустима только для текущего HTTP localhost.

Сейчас поддерживается подключение персонального ключа WB. Консервативные локальные интервалы: seller-info — не чаще раза в минуту на весь процесс, новые заказы — не чаще раза в секунду глобально и раза в минуту на магазин. `429` и `X-Ratelimit-Retry`/`Retry-After` откладывают повтор в базе. Это не универсальный планировщик всех категорий и типов токенов WB: перед их добавлением нужны отдельные бюджеты продавца/метода, учёт актуальных заголовков и лимитов.

Остальные экраны и действия (сборка, КИЗ, печать, отгрузка, Ozon, фулфилмент-доступ) пока остаются в прототипе. Они намеренно не выдают имитацию за действующие операции. Реальное подключение WB нужно проверить собственным ключом; автоматические тесты используют только вымышленные ответы и не обращаются к WB.

## Проверки

```powershell

npm.cmd run build
```

Интеграционные проверки: авторизация, блокировка межпользовательского доступа, отсутствие ключа в ответах, шифрование, объединение задач, задержка после 429, сохранение снимка при ошибке, сохранение сессий и очереди после перезапуска базы.


## Локальная имитация покупки

`npm.cmd run start:live` включает флаг `--test-purchases` только у локального сервера. В «Настройки → Подписка» выберите тариф, нажмите «Попробовать тариф», затем «Активировать без оплаты». Подписка сохраняется на сервере на 30 дней, запись помечается `is_test=true`. После этого разрешено подключить настоящий ключ WB. Деньги не списываются. Обычный `npm.cmd run server` запускается без тестовой покупки: endpoint возвращает 404. Не включать этот флаг при публичном развёртывании.


## Обновление: рабочая цепочка WB

Новая версия включает посадочную страницу, серверную регистрацию и вход, тестовую активацию подписки, подключение персонального ключа WB, загрузку новых FBS-заказов и создание поставки одного склада. В сборке доступны поиск, сканирование баркода, ввод КИЗ и печать PNG-стикера через установленный Windows-агент. Для маркированного заказа печать не означает готовность: статус ожидает подтверждение метаданных WB. Передача в доставку требует готовности всех заказов и отдельного подтверждения.

Запросы создания поставки, добавления заказов, КИЗ и передачи выполняют реальные изменения в WB. Автоматические проверки используют подменённые ответы WB; реальные операции и физическая печать в ходе проверки не выполнялись.

Для внешнего тестирования: собрать `npm run build:live`, запустить один процесс с `PORT=3041`, `DATA_DIR=.public-test-data`, `PUBLIC_ORIGIN` равным текущему HTTPS-адресу, аргументами `--serve-web --test-purchases`. Тестовая покупка намеренно доступна по внешней тестовой ссылке, деньги не списываются. Не использовать этот режим для платной эксплуатации. HTTPS-сессии получают Secure cookie.

Ограничения: поддержан WB FBS; Ozon, остатки, учёт и делегирование доступа ещё не перенесены на сервер. Ранее созданные вне этой версии поставки не импортируются. Выбор СЦ/ПВЗ с формированием коробов не реализован. Публичная ссылка через временный SSH-туннель работает пока включён компьютер и соединение. Это тестовый сервер, не завершённый промышленный релиз.
