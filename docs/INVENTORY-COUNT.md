# Инвентаризация склада

В «Остатки» добавлена вкладка «Инвентаризация» для WB и Ozon.
Выберите склад и начните пересчёт: создаётся список товаров с положительным внутренним остатком склада ВМС. Сканируйте баркод и нажмите Enter; при одном совпадении откроется ввод фактического количества, кода и адреса. Сохранённые позиции зелёные, доступны фильтры проверенных и непроверенных товаров. Прогресс хранится на сервере отдельно по кабинету и складу, общий для пользователей с доступом к нему.

Сохранение атомарно изменяет внутренний остаток и размещение, записывает историю движения. Остаток маркетплейса не меняется: передача остатков остаётся отдельной операцией. Конкурентные изменения защищены версиями; повтор запроса не дублирует движение. Перед пересчётом выполняется существующая сверка подтверждённых отгрузок. Новый пересчёт сбрасывает отметки проверки, сохраняя количества, размещение и историю.

Права: просмотр по существующему доступу к складу, изменение требует права остатков. API: GET /api/inventory-count, POST /api/inventory-count/start, POST /api/inventory-count/check. Таблицы inventory_counts и inventory_count_rows создаются автоматически.

Проверено: серверный набор 38/38, check:server, build:live, браузерный tests/browser/inventory-count.cjs (скан, количество/адрес, зелёная строка, сохранение после перезагрузки и узкий экран). Проверки синтетические, без изменения реальных остатков маркетплейсов и печати.

Уточнение: поля количества, кода и адреса редактируются прямо в строке, заполнены текущими сохранёнными значениями. Кнопка «Подтвердить» сохраняет строку и отмечает зелёным. Заполненные позиции отображаются первыми; выбранный склад сохраняется между вкладками. Отсутствующее внутреннее количество не подменяется остатком маркетплейса.

После подтверждения найденного по баркоду товара фильтр сканирования сбрасывается. Пустые позиции исключены, подтверждённые нулевые количества остаются видимыми. Для существующих пересчётов фильтр и общий прогресс обновляются без удаления истории.

Кнопка «Выгрузить в Excel» сохраняет .xlsx со всеми позициями текущей инвентаризации выбранного склада, независимо от фильтра поиска и страницы. Колонки: статус, товар, артикул/размер, баркоды, код, адрес, текущий остаток склада, количество при пересчёте, время проверки МСК, склад. Подтверждённые строки выделены зелёным. Выгружаются сохранённые значения.

Повторный скан проверенной позиции показывает предупреждение с сохранённым количеством и датой проверки. Форма не открывается автоматически; доступны «Продолжить сканирование» и явное «Пересчитать заново». Точный поиск по скану проверяет все статусы, поэтому предупреждение работает и при фильтре «Не проверены». Закрытие возвращает фокус сканеру и не изменяет количество/прогресс.

Исправление поиска 19.11: неудачный скан не меняет список, фильтры или прогресс. Точный поиск учитывает текущие баркоды каталога вместе со снимком. По физическому скану известную карточку с нулевым учётным остатком или новую после старта карточку можно добавить в текущий пересчёт без сброса проверенных позиций. В обычном списке сохраняется фильтр положительных внутренних остатков и уже проверенных строк; найденная нулевая карточка не раздувает его до подтверждения пересчёта. Количество по скану не меняется автоматически.

Источник инвентаризации — исключительно internal_stock_items.quantity («На складе» ВМС). Остатки WB/Ozon не используются ни для отбора, ни для отображения количества. Новые положительные внутренние остатки включаются в текущий пересчёт без его перезапуска. Точный скан известной карточки с внутренним нулём открывает пересчёт, не добавляя нулевые товары в общий список до подтверждения.
