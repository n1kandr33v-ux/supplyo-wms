# Инвентаризация склада

В «Остатки» добавлена вкладка «Инвентаризация» для WB и Ozon.
Выберите склад и начните пересчёт: создаётся список товаров с положительным остатком маркетплейса или склада. Сканируйте баркод и нажмите Enter; при одном совпадении откроется ввод фактического количества, кода и адреса. Сохранённые позиции зелёные, доступны фильтры проверенных и непроверенных товаров. Прогресс хранится на сервере отдельно по кабинету и складу, общий для пользователей с доступом к нему.

Сохранение атомарно изменяет внутренний остаток и размещение, записывает историю движения. Остаток маркетплейса не меняется: передача остатков остаётся отдельной операцией. Конкурентные изменения защищены версиями; повтор запроса не дублирует движение. Перед пересчётом выполняется существующая сверка подтверждённых отгрузок. Новый пересчёт сбрасывает отметки проверки, сохраняя количества, размещение и историю.

Права: просмотр по существующему доступу к складу, изменение требует права остатков. API: GET /api/inventory-count, POST /api/inventory-count/start, POST /api/inventory-count/check. Таблицы inventory_counts и inventory_count_rows создаются автоматически.

Проверено: серверный набор 38/38, check:server, build:live, браузерный tests/browser/inventory-count.cjs (скан, количество/адрес, зелёная строка, сохранение после перезагрузки и узкий экран). Проверки синтетические, без изменения реальных остатков маркетплейсов и печати.

Уточнение: поля количества, кода и адреса редактируются прямо в строке, заполнены текущими сохранёнными значениями. Кнопка «Подтвердить» сохраняет строку и отмечает зелёным. Заполненные позиции отображаются первыми; выбранный склад сохраняется между вкладками. Отсутствующее внутреннее количество не подменяется остатком маркетплейса.

После подтверждения найденного по баркоду товара фильтр сканирования сбрасывается. Пустые позиции исключены, подтверждённые нулевые количества остаются видимыми. Для существующих пересчётов фильтр и общий прогресс обновляются без удаления истории.
