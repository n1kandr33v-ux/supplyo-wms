## WB

Подключение магазинов, склады, заказы FBS, синхронизация поставок из WB и сайта, перенос заказов в существующую/новую поставку, поштучная сборка, КИЗ, стикеры, Auto-печать, отгрузка. Повторный скан одинакового товара выбирает следующий ненапечатанный экземпляр. Фокус сканера восстанавливается после диалогов. `filled` («Без проверки») принимается как сохранённая маркировка. Optional customs не означает обязательный КИЗ. Стикер отображается текстом после баркодов. Сохранять существующие правила готовности и защиты от двойной печати.

## Ozon

Магазины Client ID/API key, FBS-склады/отправления; полный каталог отдельно от заказов, точные int64 ID, все SKU-алиасы (FBO/FBS). Права ключа проверяются реально. /v1/seller/info может вернуть 403 при рабочем ограниченном ключе: используется Ozon · Client ID. Название клиента можно задать отдельно для своего аккаунта. Не требовать Admin ради названия; не добавлять доступ к финансам, чатам, аналитике.

Остатки: товар/баркоды/код/адрес/доступный остаток Ozon/локальное количество. Неизвестная запись FBS-склада — «—», не ноль и не агрегат FBO. Передача внутренних остатков в Ozon по предпросмотру и подтверждению, версии, партии, readback; нужен метод `/v2/products/stocks` (Product вместо Product read-only). Текущему подключённому ключу этого метода не хватало; это проверено через /v1/roles. Самостоятельно количества в маркетплейсе не менять.

Сборка: отдельная строка каждой штуки, собственный КИЗ и статус, без колонки количества. Если характеристика 23536=true, WMS требует КИЗ даже при optional передаче в отправлении. Также учитываются обязательные требования отправления/экземпляра. Один possible без положительного признака карточки не обязывает к КИЗ. Проверяется формат, повтор кода внутри магазина и результат Ozon; прямой проверки в «Честном знаке» нет. Ready только после passed/success для точного кода без ошибок. Ранее ready без КИЗ для маркированного товара не учитывается в готовности и допускает досканирование.

В открытом разделе сборки работает автоматическая цепочка: все экземпляры готовы → защищённый finish → подтверждение Ozon awaiting_deliver → формирование этикетки → локальный агент → квитанция. Очередь восстанавливается по серверным заданиям и сканировавшему пользователю; повторная сборка/печать не запускается вслепую после обрыва. Для печати должны быть открыты сборка и агент. В формировании этикетки сохранена задержка 45 секунд после подтверждения Ozon; физическая печать не мгновенная при подготовке файла. Ошибка агента видна, есть повтор. Многокоробочные отправления пока завершать в Ozon.

«Поставки» для Ozon показывает отдельные собранные отправления, по умолчанию awaiting_deliver, без WB-коробов. Кнопка КИЗ раскрывает коды каждой штуки, копирование исходной строки и Excel. Хранение 14 дней после сборки. Владельцу доступен отдельный архив без подписки и без действующего делегирования FF. Сотрудники/FF видят только разрешённый склад. Декоративная плашка Ozon возле заголовков удалена везде.

Реальная диагностика 18.11: каталог подключённого магазина — 53 товара. Заказ 44228316-0145-1: код был принят Ozon (passed); отдельная проверка до автоматизации подтвердила awaiting_deliver, готовую этикетку и квитанцию TSC TE200. Нельзя утверждать визуальный выход бумаги по серверной квитанции. Последующие проверки выполнялись без аппаратной печати.

## Общие модули и важные договорённости

Внутренний остаток и остаток маркетплейса раздельные. Списание только после фактической отгрузки, один раз; сборка, печать и awaiting_deliver не списывают. Отдельная вкладка «Без маркетплейса» по окончательному решению пользователя убрана. Не перезаписывать размещение и количества при обновлении каталога.

Фулфилменты, сотрудники, складские права, делегирование; учёт, зарплаты, счета. Каждый FF имеет собственный прайс; постоянные услуги клиента редактируются, цены/количество в счёте фиксируются, Excel. См. INVOICES.md, INTERNAL-STOCK.md, OZON-INVENTORY.md, OZON-STOCK-PUBLISH.md, OZON-MARK-RETENTION.md.

Android WebView APK 0.2.1 в public/downloads: крупные адрес/код/количество, баркоды ниже, двойной тап локально только на телефоне, заметки со свайпом и удалением. Телефонные отметки не меняют готовность WMS. Сохранять отдельный ключ подписи Android вне Git.

Windows print agent: исходники print-agent/windows, готовый EXE в public/downloads, loopback 17891, размеры этикеток Ozon сохраняются, дедупликация по неизменному заданию и device ID. Не тестировать на физическом принтере без задачи пользователя.

Подписки пока TEST_PURCHASES, без настоящего списания денег. Автоматический backup VPS ежедневно, хранение 14 дней; это не независимая offsite-копия. Перед миграцией получить отдельный закрытый backup БД/ключей. Ранее подготовка личного архива обсуждалась, но пользователь отменял задачу; не считать наличие копии в облаке подтверждённым.
