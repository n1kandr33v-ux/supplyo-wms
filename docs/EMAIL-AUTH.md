# Подтверждение почты и восстановление пароля

Реализовано 23 ноября 2026. Включается EMAIL_VERIFICATION=1. Старые пользователи продолжают входить по паролю. Новые пользователи создаются только после проверки кода; прежний register при включённой проверке отклоняется.

POST /api/auth/code/request принимает purpose=register/reset и email. Для регистрации также требуются name, phone, password, consent=true. Ответ содержит id, expiresIn=600 и retryAfter=60. Запрос сброса не раскрывает наличие пользователя. Для неизвестной почты возвращается тот же формат, письмо не отправляется.

POST /api/auth/code/verify принимает id, code и для сброса новый password. Пять попыток ввода, 10 минут, одноразовое потребление в транзакции. Код хранится как HMAC с серверным ключом; данные регистрации зашифрованы, пароль заранее хеширован. После сброса отзываются все старые сессии. Отправка ограничена одним письмом на адрес в минуту и двадцатью запросами с IP в час.

SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASSWORD, SMTP_FROM находятся в закрытом EnvironmentFile /etc/supplyo/mail.env. Секреты в репозиторий не входят. Допускается несколько origin в PUBLIC_ORIGIN через запятую.

Письмо содержит текстовую и HTML-версии, шесть отдельных ячеек кода и цвета supply. Geist используется при наличии поддержки, иначе Arial. Веб-шрифты и встроенные шрифты поддерживаются не всеми почтовыми клиентами.

Проверки: npm run test:auth, npm run check:server, npm run build:live, npm run test:server. Подтверждены реальная SMTP-отправка с рабочего API, доставка на служебный ящик и открытие экрана восстановления. Внешние почтовые провайдеры и полный браузерный сценарий с вводом нового пароля требуют приёмки.

Рабочая версия /opt/supplyo/releases/20261123-email-auth-v1 на прежнем backend. Новый FirstVDS обслуживает HTTPS и передаёт запросы ему. Перенос базы на автономный новый backend по-прежнему не завершён.

## Пересмотр сценариев 23.11.2026

- Регистрация: нормализация почты; проверка занятого адреса до лимитов отправки; 409 без письма и создания кода, ссылки на вход/восстановление. Аккаунт создаётся только при правильном одноразовом коде.
- Код: 6 отдельных полей; вставка целиком, замена/удаление цифры без потери соседних; автоматическое подтверждение регистрации. Блокировка параллельного запроса в интерфейсе и атомарное потребление на сервере. После ошибки сети доступна повторная проверка, после успешного подтверждения ошибка загрузки кабинета не называется ошибкой кода.
- Повторная отправка: 60 секунд на адрес, 20 разрешённых запросов с IP в час; заблокированные клики не расходуют часовую квоту. Сервер возвращает Retry-After и retryAfter, интерфейс использует их. После ошибки SMTP можно повторить без искусственной минутной блокировки. Новый успешный запрос заменяет старый код.
- Восстановление: одинаковый ответ для неизвестной почты; код и новый пароль проверяются сервером; старые сессии отзываются; старый пароль перестаёт работать. В этом сценарии остаётся кнопка сохранения нового пароля.
- Вход: неверная почта/пароль имеют одинаковую ошибку; атомарный лимит 10 попыток за 15 минут; успешный вход сбрасывает счётчик. Сессия HttpOnly/SameSite=Strict/Secure на HTTPS, выход удаляет текущую сессию.
- TRUSTED_PROXIES: только явно перечисленные прокси (loopback и собственный FirstVDS при текущей схеме) для корректного IP клиента. Нельзя включать доверие ко всем адресам.
- Автотесты входят в общий test:server: занятая почта и повторы без отправки, неверный/просроченный/использованный код, 5 попыток, замена кода, параллельное подтверждение, отказ SMTP, повторные успешные входы, блокировка неудачных, смена пароля, отзыв сессий, выход, неизвестная почта.

Остаётся приёмка реального ввода пользователем нового пароля в браузере и доставка на разные почтовые сервисы. Юридические документы для согласия пока не опубликованы; подменять их заглушками нельзя.
