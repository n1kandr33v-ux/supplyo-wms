# Передача внутренних остатков на Ozon — 18.11.2026

Кнопка «Передать остатки на Ozon» в остатках, как на WB. Предпросмотр фиксирует внутренние количества и версии; подтверждение изменяет только выбранный склад. Товары без внутреннего количества пропускаются, явный ноль передаётся. Диапазон приложения: 0–1000000. Внутренние количества при публикации не меняются; списание по-прежнему только после отгрузки.

API Ozon: POST /v2/products/stocks, product_id из каталога (не SKU), точный int64 warehouse_id, абсолютный stock; партии по 100. Ответ проверяется по каждой позиции. Результат подтверждается чтением /v2/product/info/stocks-by-warehouse/fbs по всем SKU товара, по free_stock выбранного склада. Другие склады и FBO не подменяют результат.

Подтверждения хранятся в ozon_stock_publish, привязаны к пользователю, магазину, складу и зашифрованному подключению, действуют 10 минут. Блокировки БД защищают параллельную отправку и изменение внутренних остатков. Подтверждённые партии сохраняются при частичной ошибке. Повтор сначала читает состояние Ozon: потерянный успешный ответ не приводит к новой записи. Для неподтверждённого запроса выдерживается пауза 65 секунд. Неоднозначный ответ не означает успешную передачу. Изменения абсолютные, обнуления перед установкой положительного количества нет.

Перед отправкой проверяются методы ключа через POST /v1/roles. Текущий ключ имеет Product read-only и не содержит /v2/products/stocks: функция покажет понятную ошибку до записи. Владельцу нужно разрешить изменение товаров (Product) либо выдать узкое разрешение на этот метод, если это поддерживает интерфейс Ozon. Полный Admin не нужен. Доступ к финансам, чатам и аналитике не запрашивается.

Проверено 37 серверными тестами, включая отказ без права, отдельное подтверждение, изоляцию пользователя/склада, пропуск незаданных остатков, конфликт версий, ноль, точный ID склада, потерянный ответ и повторную проверку без двойной записи. Браузерная проверка подтверждения прошла. Реальные количества Ozon при разработке и выкладке не изменялись.
