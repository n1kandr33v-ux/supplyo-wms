# Восстановление после переустановки Windows

## До форматирования C

Сохранить личный архив `supply-recovery-2026-11-13.zip` на личном Яндекс Диске, убедиться, что загрузка завершилась и файл можно скачать/открыть. Архив содержит чувствительные данные и не должен иметь публичную ссылку. Архив ZIP сам по себе не шифрует содержимое. Ещё одна копия на внешнем диске желательна.

Архив включает исходное рабочее дерево (без скачиваемых зависимостей/SDK), legacy utilities и локальные helpers, серверный согласованный backup, server config/active backend, доступ к VPS, Android signing key, SSH host/key files, локальные данные и журнал агента при наличии. Фактический состав и SHA256 указаны в manifest архива. Локальная PGlite-копия может быть копией файлов работающего процесса; для производственных данных опираться на согласованный серверный pg_dump.

GitHub отдельно содержит весь публикуемый проект, документы, схемы, синтетические тесты, APK/EXE. Не помещать распакованный личный архив в репозиторий. Учётные данные GitHub/Яндекс Диска/Hoster.ru и 2FA нужно иметь независимо от Windows; активная сессия браузера после форматирования не сохранится.

## Новая Windows, прежний рабочий VPS

1. Установить Git и Node.js 24. Войти в GitHub собственным аккаунтом.
2. `git clone https://github.com/n1kandr33v-ux/supplyo-wms.git`, открыть папку в Codex.
3. Передать PROMPT-FOR-NEW-CHAT.md. `npm ci`, затем `npm run start:live` для локальной разработки.
4. Для рабочего сайта просто открыть прежний HTTPS адрес и войти прежней почтой/паролем. Магазины и история находятся на сервере. Новый локальный сервер использует отдельную базу; пустое локальное окружение не означает потерю production.
5. При необходимости SSH восстановить known_hosts/закрытый ключ из личного архива с правильными Windows ACL; доступ root/password — в `private/server-access.PRIVATE.json`. Не копировать секрет в чат/командную историю/Git. Рекомендуется затем штатно настроить ключевой доступ, не менять доступы вслепую.
6. Установить драйвер принтера, открыть `public/downloads/supply-print-agent.exe`, выбрать принтер в настройках сайта. Если нужен старый журнал dedup, сначала остановить агент и восстановить `%LOCALAPPDATA%/ZakypitPrintAgent` из архива. Не запускать тесты на реальном принтере.

## Сборка Android и EXE

Android: Python 3, `python android-app/setup-tools.py`, **восстановить прежний** `android-app/.signing/preview.p12` из архива до первой сборки, затем `python android-app/build-apk.py`. Если ключ не восстановить, сборщик создаст новый, и APK не обновит установленную версию. Увеличивать versionCode для нового релиза. Локальная тестовая подпись не равна Play Store signing.

Windows EXE: `powershell -ExecutionPolicy Bypass -File print-agent/windows/build.ps1` запускает только этот локальный скрипт сборки, не меняет глобальную политику. Требуется Windows .NET Framework compiler, исходник и иконка в Git. Результат public/downloads/supply-print-agent.exe. Доверенные origins заданы внутри исходника.

Схема: Python с Pillow и Node-пакет elkjs в `docs/site-map/_tools` (создать `npm install --prefix docs/site-map/_tools --no-save elkjs`), затем `python docs/site-map/measure_map.py`, `node docs/site-map/layout-map.cjs`, `python docs/site-map/export_map.py`. Готовые drawio/HTML/SVG уже есть в Git.

## Только при потере VPS

Это аварийный сценарий, не обычный шаг после переустановки Windows. Не выполнять на живом сервере.

- Подготовить Linux, Node.js 24, PostgreSQL, nginx/Certbot, Poppler, роль/пользователя supplyo.
- Распаковать согласованный server tar.gz в отдельную закрытую папку, сверить SHA256/состав. В нём pg_dump custom format и encryption.key.
- Восстановить dump командой pg_restore в **отдельную новую БД**, подтвердить роли/владельцев; не использовать `--clean` на существующей production DB.
- Восстановить ровно тот encryption.key с правами только supplyo. Без него магазинные API-ключи не расшифровать. Не генерировать новый поверх старого.
- Развернуть код/lockfile, `npm ci`, build:live и backend bundle. Восстановить service/nginx из архива с проверкой путей, порта, DATABASE_URL, DATA_DIR, PUBLIC_ORIGIN и тестового режима подписок.
- Если DATA_DIR=/var/lib/supplyo, index.ts использует /var/lib/supplyo/encryption.key. Сверить сохранённую конфигурацию, не угадывать.
- До запуска фоновых workers проверить данные и scope в изолированной копии, ограничить исходящие операции. Повторный запуск старых неопределённых задач может затрагивать маркетплейсы.
- Проверить сессии/доступы/ключи/остатки и очереди, HTTPS/public health, затем вернуть трафик. Старый адрес/домен не менять без согласованной миграции; origins агента печати тоже требуют обновления.

Backup ZIP и доступы не являются публичными артефактами. В GitHub отправляется только очищенный код и документация.
